# AI-Generated Misinformation & Media Authenticity Detector

A college mini-project that extends the original fake-news detector into a **multimodal misinformation screening system**.

## What this version adds

The application accepts three kinds of content:

1. **Text / News / AI answers**
   - Existing TF-IDF + Logistic Regression fake-vs-real news model
   - Google Fact Check evidence
   - NewsAPI cross-source evidence
   - USGS earthquake and Open-Meteo weather verification when the claim contains a relevant event/place
   - New lightweight AI-text stylometric screening

2. **Images**
   - EXIF metadata inspection
   - Generative-tool metadata detection
   - JPEG Error Level Analysis (ELA)
   - Resolution/entropy checks
   - Produces a conservative `REAL-LIKELY` or `POTENTIAL FAKE / AI-GENERATED` screening result

3. **Videos**
   - Samples up to 8 frames across the video
   - Runs the image forensic screen on sampled frames
   - Aggregates frame-level signals into a video screening result

## Important scientific limitation

This is an **educational screening system**, not a forensic authentication service. AI-generated text, images and videos can be edited, compressed, cropped or generated by new models that a detector has not seen. Therefore the UI deliberately calls the outputs screening signals and shows a warning rather than claiming absolute proof.

For factual misinformation, the strongest part of the system is the evidence pipeline: external fact-checks, news sources and domain-specific public data. For media authenticity, the local forensic checks are supporting signals.

### Cross-generator generalization (image classifier)

The trained image classifier (`model/image_detector.pt`) is a small CNN trained from scratch on:
- 3,000 REAL photos (FFHQ, from the "140k Real and Fake Faces" dataset) + 3,000 FAKE images (1,500 StyleGAN-generated faces + 1,500 Stable-Diffusion-generated images from CIFAKE)
- Test accuracy: **83%** (precision 0.74, recall 0.94, F1 0.83 - see `model/image_metrics.json`)

During testing we found a real, reproducible limitation worth documenting: the model correctly classifies real smartphone photos as REAL, and correctly classifies StyleGAN- and Stable-Diffusion-generated images as FAKE, but **does not reliably generalize to images from generators it was never trained on** (e.g. DALL-E/ChatGPT-generated images) - it classified one such image as REAL with high confidence.

This is a well-documented, genuinely hard problem in synthetic-image-detection research known as the **cross-generator generalization gap**: a classifier learns the specific statistical fingerprints of the generators in its training set, and these fingerprints do not automatically transfer to a different generator architecture. Published work on this topic generally agrees that robust generalization requires training on images from many different generator families - a single architecture's fakes are not enough. For a one-month project, training on two generator families (StyleGAN + Stable Diffusion) is a reasonable, defensible scope, with this gap being an explicit, honest finding rather than an unnoticed bug.

Mitigation already in place: if a file's metadata carries near-certain evidence of a generative tool (an EXIF Software tag naming one, or PNG generation-parameter chunks like Stable Diffusion's `parameters` field), that overrides the model's prediction - because metadata, when present, is more reliable than any classifier. This does not help when the source tool (like ChatGPT's image export) does not embed such metadata.

## Files

- `app.py` — Streamlit UI for text, image and video
- `detector.py` — text cleaning, event/place detection, existing fake-news model and factual verdict rules
- `evidence.py` — external evidence APIs
- `ai_text_detector.py` — transparent stylometric AI-text screening
- `media_detector.py` — image/video forensic screening
- `train.py` — optional retraining of the original fake-vs-real news model
- `model/model.joblib` — existing trained fake-news model
- `model/metrics.json` — existing model metrics
- `validation_set.csv` — text validation set
- `tests.py` — offline regression tests for the original evidence pipeline
- `run_app.bat` — one-click Windows launcher
- `api_keys.txt` — optional NewsAPI and Google Fact Check keys

## Run on Windows

1. Install Python 3.11 or newer.
2. Double-click `run_app.bat`.
3. The first run creates `.venv` and installs the packages.
4. The browser opens the Streamlit application.
5. For stronger text verification, add the two optional keys to `api_keys.txt`.

## API keys

`NEWSAPI_KEY` and `GOOGLE_FACTCHECK_KEY` are optional. USGS and Open-Meteo do not need keys.

## Viva explanation

**Why is this different from the old fake-news project?**

The old system mainly verified textual news claims. This version is multimodal. It separates three problems: factual misinformation detection for text, AI-generated text screening, and media authenticity screening for images/videos. A video is sampled frame-by-frame, while an image is checked for metadata and forensic signals. External evidence is still used for factual claims.

**Why not simply call every AI-looking file fake?**

Because AI generation and factual falsity are different properties. An AI-written statement can be true, and a human-written statement can be false. The system therefore reports the signals separately.


## New trained-model workflow

This version uses three trainable components:
1. `input_type_model.joblib` — NEWS vs NOT_NEWS.
2. `ai_text_model.joblib` — HUMAN-WRITTEN vs AI-GENERATED.
3. `image_detector.pt` — small CNN (trained from scratch) for REAL vs AI-GENERATED.

Video is not claimed as a separate temporal deepfake model. It samples frames and applies the trained image model, then aggregates the frame predictions.

Train commands:
```text
.venv\Scripts\python train_input_type.py --data data/input_type.csv
.venv\Scripts\python train_ai_text.py --data data/ai_text.csv --max-per-class 10000
.venv\Scripts\python train_image.py --data data/image --epochs 8 --batch-size 32
```

First-time text dataset preparation:
```text
.venv\Scripts\pip install datasets
.venv\Scripts\python prepare_text_datasets.py
```
